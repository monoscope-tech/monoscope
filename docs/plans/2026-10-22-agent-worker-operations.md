# Checkout-backed impact review prototype

This directory is the research prototype. The target keeps application workflows, sandbox policy, artifacts, publication and metering in Haskell. Reuse upstream Pi over RPC/MCP and retain JavaScript only for SDK operations without an equivalent supported interface. See the [Haskell ownership plan](2026-09-30-pr-impact-review.md#haskell-ownership-revised-implementation-direction).

Pi runs on the host. The pinned harness libraries are `@earendil-works/pi-coding-agent` and `@earendil-works/pi-ai`, both `1.4.0`; `@earendil-works/gondolin` is `0.13.0`. Gondolin runs repository file and shell tools in a disposable microVM on the same server.
There is no managed sandbox dependency or review HTTP service.
The existing Haskell background job invokes the configured executable through the CodeReview effect.

Haskell prepares every application checkout and holds it until the adapter exits. The supervisor stops and reaps the child inside the checkout scope on protocol failure, callback failure or caller cancellation, so graceful child cleanup retains its source and committed skill metadata. It owns Git credentials, project/repository mirror locks, source-access checks, immutable revision refs, committed repository metadata and cleanup. Haskell replays pending receipts before starting the adapter, which requests `Checkout` and receives a credential-free private directory. It cannot clone or fetch a source as a fallback.

Haskell also owns receipt namespaces, per-run locking, bounded typed reads, replay order and acknowledgement. It supplies the adapter’s private journal path internally through `IMPACT_REVIEW_OUTBOX_DIR`. The SDK writes each receipt synchronously before transmission; Haskell checks the matching journal entry, calls the existing database callback, then unlinks and syncs before acknowledging. Failed callbacks leave receipts pending. Replay runs before child startup, source access and new inference. The JavaScript adapter no longer scans or deletes receipts.

Prepared-workspace identity, integrity checks, preparation and atomic publication also run in Haskell, through the shared `Data.Effectful.AgentWorkspace` effect and `monoscope workspace` CLI. `sandbox.mjs` translates VM commands to Gondolin SDK calls; `workspace.mjs` calls the native CLI and resumes verified checkpoints. There is no JavaScript cache-policy fallback. The same effect and `monoscope workspace check` now own frozen-regression budgets, revision checks, fresh offline verifier workspaces, test-patch placement, source fingerprints, result classification, private reports/logs and durable execution receipts. The SDK bridge executes native-selected commands and streams bounded output; the agent adapter transfers finished logs into the agent VM. There is no JavaScript verifier-policy fallback.

Research callers must supply `preparedCheckout` metadata matching their request and an existing checkout at the exact head. It includes `repositorySkills`, a private metadata directory containing the two committed skill roots, and `rootInstructions`, the pinned root instruction text. `evaluate.mjs` reads it from the case’s `checkout` field; `reviewbench.mjs` reads a private metadata file through `IMPACT_REVIEW_CHECKOUT`. These tools no longer prepare source repositories.

### Reuse a prepared project workspace

An operator can build one committed baseline in an isolated VM and publish its disk checkpoint to private server storage. The worker loads a fresh COW overlay for the agent and each verifier. It fetches only Git objects into the existing checkout, preserving timestamps and compiled outputs for unchanged files.

Create a private request file with `projectId`, credential-free `repository`, and the exact `base` revision. Select a trusted preparation script that follows that repository’s build instructions; keep the script on the host outside customer checkouts. Dependencies must exist in the pinned image or an explicit dependency archive: preparation has no network or production credentials.

```sh
monoscope workspace prepare \
  --request /srv/monoscope/baseline.json \
  --checkout /srv/checkouts/project \
  --script /srv/monoscope/prepare-project.sh \
  --image /srv/monoscope/guest-image \
  --cache /srv/monoscope/agent-cache \
  --bridge /srv/monoscope/impact-review-worker/sandbox.mjs
```

Set `IMPACT_REVIEW_PREPARE_SCRIPT=/srv/monoscope/prepare-project.sh` on the worker, using the same script bytes. `IMPACT_REVIEW_CACHE_DIR` selects private persistent storage. Without a dependency archive, an absent matching entry uses the ordinary clean image. A configured dependency archive requires a matching prepared workspace and a trusted preparation script; a miss stops before VM creation or model inference. Invalid or corrupted entries fail before model work. The model cannot select or promote a checkpoint.

Keys bind project, repository, base commit, image build ID, preparation-script hash, and the dependency archive SHA-256 when supplied. The Haskell loader verifies the private manifest, complete disk SHA-256, size, and SDK checkpoint toolchain identity. It preserves existing cache keys, including nested dependency fingerprints. Preparation clones committed files only, checks that tracked source and HEAD remain unchanged, and atomically publishes under a host lock. Each receipt/report carries the prepared disk fingerprint; frozen reproduction and both verification executions must use the same workspace. Legacy receipts without that field mean the pristine image and remain replayable.

Pass `--dependencies /path/to/archive.tar` to include a host-owned dependency archive. Set `IMPACT_REVIEW_DEPENDENCY_ARCHIVE` to the same archive on the worker. The host streams this one regular file to `/run/monoscope-dependencies.tar`, checks its hash inside the offline VM, and closes the file before running the trusted preparation script. The host does not extract it. The script can extract package content into the VM's private cache and restore dependencies with the package manager's offline mode. The SDK bridge closes its VM if its parent pipe disappears during preparation. The checkpoint retains the installed dependencies; reviews and verifiers do not receive a host cache mount. The frozen check must rebuild outputs and restore dependencies from the current revision when manifests change; cached output alone is not verification.

For npm, use a dedicated project cache and archive only the needed `_cacache/content-v2` blobs. Exclude host registry indexes, logs, configuration and credentials. A trusted preparation script can extract those blobs into `/home/review-agent/dependency-cache`, then run `npm ci --offline --ignore-scripts --no-audit --no-fund --cache /home/review-agent/dependency-cache`. The lockfile must pin the packages and integrity hashes. npm checks package integrity. Native modules may need a separate approved build step inside the VM. Archive creation/fetching is an operator task; this change adds no network access or automatic dependency resolver.

The archive is immutable preparation input. Its digest and byte count are retained in the private manifest, and different bytes select a new cache entry. Missing or symlinked archives fail. Changed bytes select a new key that must be prepared before review; a change during copying aborts preparation. Existing unseeded cache identities remain compatible. Dependency archive bytes remain unpriced resource facts; they are not customer charges.

`workspace_cache` events report hit/miss/disabled, checkpoint bytes, fingerprint, and lookup duration. The private manifest records creation time, preparation duration, resources, bytes, and `unpriced` status. Those preparation/storage facts are not yet ingested into customer/project Usage or priced; no charge is implied. Automatic preparation jobs, retention/eviction, full server/DB profiles, and production Linux measurements remain unfinished. Do not remove a checkpoint while overlays are using it.

## Source-fix library

`fix.mjs` exports `fixIssue(request, options)`. It shares Pi, checkout/cache preparation, skills, scoped telemetry/knowledge adapters, model metering, and verifier execution with the advisory reviewer. The request adds an issue UUID and starts at its pinned base. The caller supplies a persisted attempt UUID, private artifacts, an event/metering sink, and these required host callbacks:

| Callback | Contract |
| --- | --- |
| `admitTest(artifact, signal)` | Review that the patch changes only relevant tests/fixtures and exercises the actual reported bug. Return `{Right: "recorded rationale"}` or `{Left: "reason"}`. |
| `recordStep(step, signal)` | Persist `Observe` and `ProposeCandidate` through the authorized phase store before returning `{Right: ...}`. A rejection or missing acknowledgement cannot advance the local workflow. |
| `validateFix(result, signal)` | Check the persisted verified run and identities before returning `{Right: ...}`. A result is not returned without host acceptance. |

The application job below connects the separate admission operation to the fix engine. The caller must authorize the issue/repository, persist its attempt before model work, and durably handle `model_response` and `regression_execution` events. The dispatcher and fresh-attempt retry path are implemented; customer launch UI, budget reservations, and VM/build resume remain pending.

The CLI accepts a fix envelope `{tag: "FixTask", contents: {request: <common request>, issueId: <UUID>, imageBuildId: <UUID>}}`; advisory callers keep their existing flat request. Haskell exposes separate `reviewRepository` and `fixRepository` operations, with distinct review/fix run-ID types. `CodeReview.Types` shares the refined revision, phase, and wire types with the phase store without introducing an import cycle. The interpreter parses fix results into `FixResult`, checks host acceptance, and requires the final payload to match it exactly. Admission and phase calls share the bounded RPC budget, and later state/query calls invalidate accepted results.

`Admit` frames carry the regression artifact; `Phase` frames carry a stable delivery ID, attempt ID, and typed step. The CLI persists phases before transmission, awaits each acknowledgement, and retires them only after acceptance. Fix outboxes live under `<usage-dir>/fixes/<runId>`; advisory outboxes retain their existing path. Recovery sends usage/execution receipts before dependent phases and finishes before new model work. Rejected phases remain pending. This is delivery recovery, not complete issue-job resume orchestration or a background outbox drain.

The server has a shared `Models.Projects.AgentUsage` ledger with distinct typed review/fix targets. Migration `0236` adds explicit fix-run references to the existing tables; no review identity is invented for a fix. Attempts pin billing before launch, and acknowledged model/check receipts persist against that attempt. Project and administrator customer totals include both workflows. ## Native checkpoint archive and restore

`monoscope workspace archive` and `monoscope workspace restore` use the existing Haskell MinIO SDK. Supply the same `--request`, `--cache`, `--image`, `--bridge`, `--script` and optional `--dependencies` arguments as workspace preparation, plus `--remote /etc/monoscope/workspace-store.json`. This is an operator interface; the agent receives no storage credentials or remote-storage tool. Existing jobs do not automatically archive or restore a cache miss yet.

The private JSON configuration requires `endpoint`, `bucket`, `region`, `accessKey`, `secretKey`, and `maxBytes`. Use an explicit endpoint on your servers and an existing private bucket. `maxBytes` limits one checkpoint's logical size; it is not a total disk quota. For example:

```json
{
  "endpoint": "https://minio.internal:9000",
  "bucket": "monoscope-private",
  "region": "us-east-1",
  "accessKey": "REPLACE_WITH_HOST_CREDENTIAL",
  "secretKey": "REPLACE_WITH_HOST_SECRET",
  "maxBytes": 536870912
}
```

Keep this file outside repositories with mode `0600`. Endpoint user info, query strings and fragments are rejected; TLS verification remains enabled. The CLI reads bounded regular files and never sends this configuration to Gondolin. It does not create a bucket or select a managed endpoint.

Objects use `agent-workspaces/v1/PROJECT/IDENTITY/`. The identity includes repository, pinned base and image build, preparation-script digest, and optional dependency archive digest/size. Archive verifies the local entry, streams the disk to `DISK_SHA256.qcow2`, checks the stored size, then publishes the digest-associated `DISK_SHA256.json` manifest followed by `manifest.json`. A request with `expectedCheckpoint` restores through its digest manifest, independently of the latest pointer. The disk hash is not an S3 ETag.

Restore verifies bounded metadata and the exact identity before downloading. It enforces both the configured size limit and declared byte count, checks SHA-256, inspects the checkpoint's image ID, and normalizes the manifest's image directory to the current host. It publishes a synced local directory only after these checks pass. Failure removes temporary restore files. A valid local hit avoids remote transfer; a corrupt local entry fails closed. The pinned base image must already be available on the destination host. No guest RAM, process or watcher state is restored.

Transfers retain private project-scoped records in `CACHE/PROJECT/transfers/`. Each records identity, direction, start time, and started/completed/failed outcome. Completion includes checkpoint bytes/digest and elapsed time; failed or interrupted transfers have unknown transferred bytes. All are explicitly unpriced. These records are not yet ingested into customer usage summaries and do not establish storage byte-time, total network traffic or charges. SIGKILL can leave a started record and temporary files; orphan reconciliation and automatic cleanup remain pending. Remote blob/multipart retention is also not configured by this command.


## Native checkpoint eviction

Run `monoscope workspace prune --request /private/prune.json --cache /srv/monoscope/cache --remote /etc/monoscope/workspace-store.json`. The request is `{"projectId":"PROJECT_UUID","maxBytes":536870912}`; zero is allowed when all idle archived entries should be considered. This is an explicit operator command, not an automatic job scheduler or an agent tool.

The budget covers that project's `workspaces/` and `leases/` trees. Counts come from native `du -sk`, using allocated KiB converted to bytes and deduplicating hard links across those trees. Filesystem compression/cloning can affect reported allocation. This does not measure total server free space, Git mirrors, shared toolchain images, journals or billable storage byte-time. The remote configuration's `maxBytes` remains a separate per-checkpoint transfer limit.

The pruner visits entries by `last-used.json`; successful native lookups refresh this separate marker. Legacy entries without a marker use manifest creation time. Manifest and disk fingerprints stay unchanged. Before eviction, Haskell checks the owned directory's names, manifest identity, directory key and disk digest. The matching per-digest S3 manifest must have the same identity, hash and size, and a bounded streamed read must hash to that digest. A same-size corrupted remote object cannot authorize local deletion. Invalid, unarchived or unavailable entries remain local.

Live immutable lease references pin their canonical entry. Lookup, lease acquisition, lease cleanup, archive, restore and prune share a project lock, so eviction cannot race a new reference. The lock is released while the borrower uses its lease; pruning holds it during remote verification. That verification can delay cache operations for this project. Other projects have independent locks. Safe entries retire through a private temporary directory before removal; ordinary exceptions clean it up.

The JSON report includes `beforeBytes`, `afterBytes`, `leaseBytes`, `targetBytes`, typed entry outcomes and unrecognized names. If retained entries or lease allocation leave the cache above target, the command prints the report and exits unsuccessfully. It does not claim the budget was met or delete active/unverified state to force it. Unknown names, directory symlinks, unexpected entry contents, other projects, Git mirrors and toolchain images are preserved.

Private journals in `CACHE/PROJECT/prunes/` retain started, running and finished states, the partial/final report and elapsed time. Elapsed time includes the initial inventory; a journal starts before scanning entries. A stopped run can leave an incomplete journal. Resource costs remain unpriced, and these maintenance records are not yet customer usage or charges. SIGKILL can also leave `.prepare-*`, `.restore-*`, `.evict-*` or lease directories. They remain visible in allocated usage; safe orphan reconciliation, remote retention and automatic admission/maintenance scheduling are still unfinished.
